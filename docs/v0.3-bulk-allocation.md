# v0.3 bulk mapping allocation

When an existing RTU or TCP client is loaded as a Bulk Generator template, its TCP Server mappings are cloned as a layout rather than reusing their original addresses.

For each Modbus TCP address space (`coil`, `discrete_input`, `holding_register`, `input_register`) the allocator:

1. preserves the relative layout of the source device mappings;
2. starts the generated block after the highest existing occupied range;
3. uses the full source-device block width as the per-device step;
4. accounts for 32-bit `int32`, `uint32`, and `float32` values as two 16-bit Modbus registers per mapped value.

This prevents mappings generated in the same batch from overlapping each other or the existing project.
